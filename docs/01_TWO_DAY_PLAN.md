# 이틀 압축 개발 계획

최우선 원칙은 기능 수보다 필수 요구사항과 보안 불변조건을 완성하는 것이다. 보안 통제는 확장 기능으로 보지 않으며 일정이 부족해도 제거하지 않는다.

## 2026-07-12 - 범위 확정, 설계, 핵심 구현

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 과제 최소 요구사항 페이지 확인 | 모든 항목에 REQ-ID와 인수 조건 부여 |
| 2 | P0/P1 범위 동결 | P0 이외 기능 추가 중단 |
| 3 | 화면 흐름, ERD, 권한표, 상태 전이, 위협 모델 | 설계 결정과 이유 기록 |
| 4 | Django 프로젝트·테스트·환경 골격 | 새 환경에서 설치·마이그레이션·실행 가능 |
| 5 | P0 사용자 흐름을 기능 단위로 구현 | 정상·실패·권한 테스트를 기능과 함께 작성 |
| 6 | KISA 적용성 매트릭스 1차 판정 | 49개 항목을 A/N/A로 분류하고 근거 기록 |
| 7 | 당일 보고서 원고 동기화 | 요구사항·설계·구현 장 초안 완성 |

오늘 기능 동결 이후에는 과제 최소 요구사항이 아닌 UI 효과나 확장 기능을 추가하지 않는다.

## 2026-07-13 - 보안 검증, 문서화, 릴리스, 제출

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | P0 전체 회귀 테스트 | 모든 REQ-ID에 TEST-ID와 성공 결과 연결 |
| 2 | IDOR, 가격·상태 변조, XSS, CSRF, SQLi, 파일, 세션 테스트 | 성공한 공격 0건 또는 수정·잔여위험 기록 |
| 3 | 정적·의존성·시크릿·Django 배포설정 검사 | 미조치 Critical/High 0건 |
| 4 | 발견한 문제 수정 후 회귀 테스트 | SEC-ID별 수정 전후와 재시험 결과 기록 |
| 5 | 클린 환경 README 검증 | 문서 명령만으로 설치·실행·테스트 성공 |
| 6 | Git 전체 이력 시크릿 검사 및 Public 공개 | 로그아웃 상태에서 저장소 접근 가능 |
| 7 | `v1.0.0` 태그와 최종 SHA 확정 | 보고서에 저장소 링크·태그·SHA 기재 |
| 8 | PDF 생성·렌더링·육안 검수 | 잘림, 겹침, 깨진 한글, 잘못된 링크 0건 |
| 9 | 제출 및 재확인 | 파일명·GitHub 링크·PDF 열람 최종 확인 |

## 필수가 아니면 제외할 기능

- 실시간 채팅과 WebSocket
- 카드 결제, 에스크로, 배송 API
- 소셜 로그인, 이메일·SMS 인증
- 사용자 주소·전화번호 수집
- 외부 URL 이미지 가져오기
- 추천, 지도, 경매, 쿠폰, 포인트
- 모바일 앱, 다국어, 알림, 복잡한 통계 화면
- 클라우드 배포 자동화

2026-07-13 정정: PDF 25~29페이지를 시스템 기능 기준으로 적용하면서 `실시간 전체 채팅`은 위 제외 조건에 해당하지 않게 되었다. WebSocket 자체는 구현 방식 중 하나일 뿐이며, 전체 채팅의 실시간 갱신을 안전한 WebSocket·SSE·polling 중 하나로 구현·시험해야 한다. 현재는 미구현이다.

## 일정 중단 조건

- 최소 요구사항 페이지를 받지 못하면 `최소 요구사항 충족`을 확정적으로 주장하지 않는다.
- Critical/High 문제가 발견되면 보고서나 UI 작업보다 수정과 회귀 테스트를 우선한다.
- 코드 동결 후에는 제출 차단 오류와 보안 결함만 수정한다.
